## Behavior implemented

- `InteractionPromptView` is a temporary IMGUI placeholder on the Player prefab; the UI phase replaces it.
- `IsVisible` and `CurrentLabel` are explicit state. `OnGUI` draws only when `IsVisible` and the label is non-empty.
- `OnEnable` subscribes to `PlayerInteractor.TargetChanged`; `OnDisable` unsubscribes and hides.
- `Update` calls `Refresh` each frame so pause, eligibility, and destroyed-target changes are caught even without a notification.
- Visibility requires a live interactable that returns true from `CanInteract`, and `Time.timeScale > 0`.
- Label format is `"<interaction prompt> [<InteractKeyLabel>]"`, for example `Interact [E]`. The key comes from `PlayerInteractor`; the view never hard-codes it.
- The view does not read input, change `Time.timeScale`, or touch cursor lock/visibility.
- `SetupPlayerPrompt` reuses an existing view and rewires `_interactor`; `ValidatePlayerSetup` fails when the view is missing or points at a different interactor.

### Repair attempt

The first PlayMode run failed 5 of 31 tests with `MissingReferenceException` from `SimpleInteractable.CanInteract`, called by `InteractionPromptView.Refresh` after a test destroyed its target. The view's `IsAlive` helper copied the interactor's expression `unityObject == null || unityObject != null`, which is always true under Unity's overloaded null check, so a destroyed object passed the guard. The view now uses `ReferenceEquals(unityObject, null) || unityObject != null`. Compile, EditMode, and PlayMode were rerun and are clean.

## Known risks and limitations

- The IMGUI label uses the built-in font and a fixed 360x34 px box at `Screen.height - 96`; it is readable but not final UI and may overlap other placeholders at unusual resolutions.
- `PlayerInteractor.IsAlive` still contains the original tautological Unity-null expression. The prompt view uses a corrected check, but an external `TryInteract` in the same frame a target is destroyed could still throw until the interactor helper is corrected.
- The view calls `CanInteract` every frame, which is cheap for current interactables but adds per-frame work as interactable counts grow.
- `CurrentLabel` is a display string, not localized; localization is out of Phase 3 scope.
- Prompt visibility depends on `PlayerInteractor` resolving the target first; a script execution-order change does not break it because `TargetChanged` triggers an immediate refresh, but `IsVisible` can lag one frame in edge cases.
